# Private Advisor Phase 2.1 设计规格（V1）

## 1. 目标定义

Phase 2.1 的目标是把“Phase 2 的能力点”推进为“可扩展产品底座”，优先完成两件事：

1. 分身玩法配置化扩展（从硬编码规则升级为可配置系统）
2. 桌面端交互 MVP 预备（先打通交互契约与事件边界，不直接做完整桌面 UI）

本阶段默认继续采用“移动端先行、后端跟进、桌面契约预留”的节奏，前端视觉雏形放在后续小迭代。

## 2. 范围边界

### 2.1 本阶段要做

- 建立分身玩法配置模型（人格、进化阈值、成长倍率、反馈文案）
- 建立配置读取与默认配置策略（本地内置配置 + 版本号）
- 建立桌面交互能力契约（全局悬浮、托盘、快捷召唤等能力开关）
- 为后端预留配置同步与校验接口契约（先契约、后能力）
- 补齐端到端测试基线，保证已有核心流程不回退

### 2.2 本阶段不做

- 不做完整 iOS 产品视觉重构（仅保留必要挂载点）
- 不做 macOS/Windows 正式交互层实现
- 不做复杂多人格剧情、社交化玩法与经济系统

## 3. 方案概览

### 3.1 配置化玩法层（Mobile Domain）

新增 `AvatarPlayConfig` 作为分身玩法统一配置对象，包含：

- `configVersion`
- `personalityModes[]`
- `evolutionStages[]`
- `qualityWeights`
- `feedbackTemplates`

由运行时通过 `AvatarConfigRepository` 提供默认配置，业务逻辑不直接写死阈值和文案。

### 3.2 桌面交互契约层（Shared Contract）

在现有 `DesktopCapability` 基础上扩展为 `DesktopInteractionContract`：

- 能力开关：overlay / tray / quick invoke / notification sync
- 平台级限制：macOS / windows 支持矩阵
- 降级策略：能力不可用时返回 fallback 行为

### 3.3 服务端契约预留（API）

新增轻量接口契约（可先 mock）：

- 获取可同步分身配置摘要
- 校验客户端上传的配置版本兼容性
- 返回推荐升级提示（可选）

目标是提前固定客户端与服务端边界，避免后续桌面端接入时重复返工。

## 4. 数据流与职责

1. 客户端启动 -> 读取默认分身配置
2. 分身成长引擎按配置计算成长/进化
3. 人格策略按配置输出 prompt 前缀和反馈风格
4. 桌面能力层读取契约，判断哪些功能可见
5. API 返回配置版本信息，客户端决定是否提示更新

## 5. 验收标准

- 所有成长/进化关键逻辑不再依赖硬编码常量
- 人格模式可通过配置增删（至少支持新增模式不改核心逻辑）
- 桌面交互契约有可测试默认值与降级路径
- Mobile + API 测试全绿，新增测试覆盖配置加载与契约校验

## 6. 风险与缓解

- 风险：配置模型过度设计导致实现变慢  
  缓解：保持 MVP 字段最小集，只覆盖当前已实现玩法

- 风险：桌面契约抽象过早偏离真实需求  
  缓解：只定义能力开关与 fallback，不提前设计复杂生命周期

- 风险：服务端契约先行但实现滞后  
  缓解：先提供 mock/静态版本，确保客户端与测试可运行

---

该规格仅用于 Phase 2.1 首轮推进。进入实现前，需输出与本规格对应的任务级实施计划，并按任务粒度验证。
