# 移动端信息架构与顾问上下文流设计（Phase 2.2 草案）

## 1. 目标与背景

本轮设计目标是优化移动端页面层级与跳转路径，让用户在“今日行动”与“顾问支持”之间切换更顺畅，同时保持模块边界清晰，避免功能耦合过早带来的复杂性。

目标聚焦：

1. 保持底部导航稳定，降低认知成本。
2. 打通 `今日 -> 顾问` 的上下文对话入口，提升连续体验。
3. 明确“分身交互层”与“页面导航层”的职责边界。

## 2. 设计边界（已确认）

### 2.1 模块关系

- `今日` 与 `宣言书` 是平行关系，不互相绑定数据。
- `挑战` 与 `宣言书` 可以无关联独立存在。
- `宣言书` 支持随时修改，并提供月度 review 提醒。
- 当前阶段不做“今日记录自动关联宣言书”的产品功能联动。

### 2.2 页面定位

- `今日`：感谢昨天的自己 + 挑战今天的自己（高频行动入口）。
- `宣言书`：长期目标与执行计划的维护区（中低频编辑）。
- `顾问`：独立顾问会话区（可接收上下文，但不强制写回其他模块）。

## 3. 信息架构与导航规范

底部导航固定为五栏：

- `今日`
- `宣言书`
- `顾问`
- `历史`
- `设置`

规则：

1. 底部导航是唯一全局主导航，不新增并行导航体系。
2. 悬浮分身不是导航入口，不承担分页跳转职责。
3. 所有跨页主流程优先通过现有底部导航与页面内 CTA 完成。

## 4. 核心流程：今日到顾问（推荐方案 B）

### 4.1 触发时机

- 用户在 `今日` 页面完成核心输入（昨日感谢 + 今日挑战）后，显示底部主 CTA：
  - `带着今天的状态问顾问`

### 4.2 跳转策略

- 点击 CTA 后进入 `顾问` 页面（独立分页）。
- 此次进入携带来源上下文标记：`from=today`（仅初始化顾问对话，不建立跨模块绑定）。

### 4.3 顾问开场

- 顾问可基于上下文给出首条引导，例如：
  - “我已看到你今天的挑战方向，想先拆解执行步骤，还是先排除阻碍？”

### 4.4 返回与连续性

- 顾问页展示 `返回今日` 操作。
- 返回后恢复到今日页原锚点（如完成卡片或输入区域附近），避免用户迷路。

### 4.5 降级与异常

- 若今日内容未填写，CTA 文案降级为：
  - `先写下今天，再让顾问帮你拆解`
- 若上下文注入失败，顾问页正常进入并使用通用开场，不阻塞流程。
- 顾问建议默认不自动回写 `今日` 或 `宣言书`。

## 5. 悬浮分身规范（本轮）

保留“陪伴感与可玩性”，不引入页面跳转：

- 支持拖拽移动。
- 支持基础动作反馈（呼吸、眨眼、轻微响应动作）。
- 点击悬浮分身不跳转到任何分页。

## 6. 交互与视觉约束（ui-ux-pro-max 对齐）

结合本轮检索结果与现状，落地以下约束：

1. 导航与路由：逐步向命名路由/声明式路由收敛，减少匿名跳转。
2. 可点击区域统一提供清晰反馈（状态变化、轻量动效、`cursor/触控` 语义一致）。
3. 强化低风险一致性改造：间距栅格、标题层级、卡片语义，不在本轮引入高复杂抽屉式顾问。
4. 保持“顾问独立页”与“今日上下文入口”并存，先验证核心体验，再决定是否升级为半屏沉浸方案。

## 7. 验收标准（设计级）

1. 用户可明确区分 `今日`、`宣言书`、`顾问` 的职责与边界。
2. 用户在今日完成输入后，能一键进入顾问并感知“上下文被理解”。
3. 用户从顾问返回今日时，不出现位置丢失或状态断裂。
4. 悬浮分身不会造成误触跳页。
5. 不引入任何“今日与宣言书自动联动”的新行为。

## 8. 暂不纳入本轮

- 半屏/抽屉式顾问（交互复杂度较高，后续可单独评估）。
- 顾问建议自动写回今日或宣言书。
- 宣言书与挑战的自动映射策略。
