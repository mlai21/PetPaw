# 私人顾问 App 产品设计规格（V1）

## 1. 背景与定位

本产品的核心不是“日记 + AI 问答”，而是一个可长期成长、可持续激励用户行动的数字分身系统。  
日记、宣言书、挑战记录是“给数字分身注入灵魂”的主要输入渠道。

一句话定位：

> 帮助用户每天向更强版本推进一小步的私人顾问与数字分身产品。

## 2. 目标用户与阶段

- 用户阶段：执行期（知道目标但容易拖延、中断，需要持续引导与纠偏）
- 产品风格：多人格可切换（治愈陪伴 / 热血成长 / 冷静军师 / 自定义混合）
- 平台优先级：iOS + Android 首发，macOS + Windows 后续上线（同一产品主线）
- 隐私策略：混合模式（敏感本地、非敏感可同步）

## 3. 版本策略与边界

### 3.1 一期原则（必须）

1. 先把“日记、宣言书”打磨好，保证输入质量与日常可坚持性
2. 一期必须有数字分身（基础可视化成长反馈）
3. 分身玩法二期再系统化扩展
4. 一期架构必须为二期玩法与潜在独立 App 预留扩展接口
5. macOS 与 Windows 必须纳入产品路线图（不是可选项）

### 3.2 一期（MVP）做什么

- 晨间记录：肯定昨天、感谢对象、观察到的优秀行为、挑战今天
- 今日挑战：支持来自宣言书计划 + 用户自定义挑战
- 日常记录：随手记录进展与关键片段
- 目标宣言书：多目标（目标-执行计划-达成奖励-撰写日期）
- 顾问聊天：基础问答 + 联网搜索 + 长期记忆
- 数字分身：基础形象、能量状态、等级/阶段成长
- 账号体系：手机号 + 验证码注册/登录
- 注册后分身创建：参考图上传 + 风格选择 + 4 候选生成/重跑 + 选择 + 分身命名（必填）+ 期望输入（选填）
- 月度回顾：每月一次，不做高频复盘
- 架构预留：账号、同步、记忆分层、分身状态模型需可直接复用到 macOS/Windows

### 3.3 一期不做什么

- 一期不做 macOS/Windows 正式客户端与桌面常驻桌宠
- 深度社交、PVP 对战系统
- 复杂 3D/高成本美术资产系统
- 复杂自动化 Agent 执行链路
- 分身声音输入与语音克隆（上传音频/录音）后置到下一版

## 4. 核心信息架构

- `今日`：晨间记录 + 今日挑战 + 宣言书核心卡片常驻
- `记录`：日常成长记录流（肯定、感谢、观察、进展）
- `宣言书`：目标、执行计划、奖励与进度
- `顾问`：问答、搜索、建议、记忆调用
- `分身`：形象、成长状态、已解锁内容、人格模式
- `月度回顾`：月度汇总、洞察、下月建议

## 5. 关键产品循环

### 5.1 日常循环（高频）

1. 用户晨间完成自我暗示与挑战设定
2. 系统结合宣言书计划推荐今日挑战
3. 用户白天记录行动与观察
4. 系统更新分身能量与成长反馈

### 5.2 月度循环（低频）

1. 聚合当月记录与挑战结果
2. 输出优势模式/阻碍模式/改进建议
3. 回写宣言书执行计划（建议修订）

## 7. 隐私与记忆分层

- 私密层（本地）：日记原文、敏感事件、敏感人名
- 成长层（可同步）：挑战完成、里程碑、月度洞察
- 顾问层（可控同步）：人格设置、偏好参数、展示配置

用户控制能力：

- 仅本地保存此条记录
- 允许该条参与顾问建议
- 允许该条跨设备同步
- 一键导出/删除个人记忆

## 8. 分身成长与反馈机制（一期）

成长触发：

- 完成挑战 -> exp 增长 + 能量上升
- 连续行动 -> streak 增加，达到阈值后触发阶段进化
- 月度达标 -> 解锁皮肤/徽章（可后续扩展）

行为原则：

- 支持手动暂停进化
- 中断时只做“能量回落 + 恢复建议”，不做羞辱式反馈
- 人格可切换，但成长主线唯一（数据不割裂）

## 9. 技术架构草图（移动优先）

- 客户端：Flutter（iOS + Android）
- 本地层：SQLite + 本地加密
- 云服务：账号、同步、搜索结果转译、记忆摘要存储
- AI 编排层：
  - 对话
  - 挑战建议
  - 月度洞察生成
- 事件层：统一记录挑战完成、连胜、中断、回顾完成等事件

扩展预留：

- 分身玩法系统与业务核心解耦（状态机 + 配置驱动）
- 后续可将“分身玩法”抽离为独立 App，并复用账号、成长状态与记忆摘要
- macOS/Windows 客户端建议复用 Flutter Desktop 能力，先同步核心闭环（记录/宣言/顾问/分身状态），再扩展桌面伴随能力

## 10. 商业化方向（先后顺序）

一期：

- 免费：基础成长与基础分身体验可完整使用
- 会员：更多人格槽位、皮肤样式、更深洞察报告、更高记忆容量

二期及以后：

- 进化分支、羁绊任务、活动外观
- 分身社交（名片、互访、鼓励互动）
- 轻对战机制（先非零和，再评估 PVP）

原则：

- 付费买表达与沉浸，不买核心成长权利

## 11. 成功指标（MVP）

- D7 留存、D30 留存
- 周均晨间记录完成率
- 挑战创建到完成转化率
- 月度回顾完成率
- 分身交互触发频次（查看/切换人格/成长反馈点击）
- 用户主观价值评分（“它是否帮助我更强”）

## 12. 风险与应对

- 风险：游戏化过重导致“刷数值”而非真实成长  
  应对：成长计算加入“行动质量权重”，避免纯数量导向

- 风险：AI 建议泛化、无个人感  
  应对：强化长期记忆摘要质量与个性化提示模板

- 风险：隐私顾虑影响使用  
  应对：明确本地优先范围、逐条授权与一键删除能力

## 13. 注册后分身创建流程（一期）

流程入口：

- 用户在账号页完成“手机号 + 验证码”注册/登录后，进入分身创建向导。

分身创建向导（2 步）：

1. 形象生成与选择
   - 上传参考图（建议 1-3 张）
   - 选择风格（单选）
   - 触发一次生成 4 个候选分身形象
   - 可反复重跑，直到满意
   - 支持预览基础动画（无声）
   - 必须选择 1 个候选后才可下一步

2. 分身设定补充
   - 分身命名：必填（建议 2-12 字符，支持中英文数字，含敏感词过滤）
   - 期望输入：选填（可跳过）

产品原则：

- 分身初始状态是白纸，后续主要通过日记、宣言书、挑战记录注入“灵魂”。
- 注册阶段的“期望输入”仅作为参考信号，用于后续交互校正，不硬绑定分身行为。
- 一期不做声音输入与语音生成能力，避免首版复杂度失控。

---

该文档定义一期产品边界与二期扩展方向。后续实施计划应以“一期先打磨输入质量与基础分身反馈”为最高优先级。
